# Working Agreement

## For Jim's review team

1. Work in a branch named for the project and purpose.
2. Begin with an inventory or comparison; do not delete historical candidates during the first pass.
3. Propose one canonical entry point and explain the evidence for choosing it.
4. Move superseded material only after a second reviewer agrees.
5. Keep exact paths in review notes so decisions remain traceable.

## Suggested first-pass deliverable

For each project, add a `CANONICAL_STATUS.md` containing:

- purpose;
- recommended entry point;
- current version or `undetermined`;
- files compared;
- tests or evidence checked;
- unresolved conflicts;
- recommended archive candidates;
- next action.

The repository owner is the originator and idea lead. Technical reviewers are responsible for explaining consolidation decisions in plain language rather than silently restructuring the work.
